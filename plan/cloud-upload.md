# Загрузка Shorts из облака (приватно, публикует владелец)

Цель: ролик загружается на канал @KapisWorldTV из облачной сессии, даже когда Mac выключен. Загрузка всегда **приватная**: кнопку «Опубликовать» нажимает владелец в YouTube Studio.

## Как это устроено

- Ключи не лежат в репозитории (он публичный). Облачная среда «ютуб» хранит их в переменной окружения `YT_TOKEN_JSON` (содержимое `secrets/token.json`, одной строкой).
- `scripts/yt_creds.py` читает ключи из `YT_TOKEN_JSON`, иначе из `YT_CLIENT_ID` + `YT_CLIENT_SECRET` + `YT_REFRESH_TOKEN`, иначе из `secrets/token.json` (на Mac). В сообщениях об ошибках значений нет.
- В среде «ютуб» разрешены хосты `oauth2.googleapis.com` и `youtube.googleapis.com` (добавлено 2026-11-16). Остальной интернет закрыт.
- Права токена: `youtube.upload` (только загрузка) и `youtube.readonly`. Удалять и править чужие данные токен не может.

## Что нужно сделать владельцу (один раз)

1. **Google Cloud Console** → проект `kapis-world` → «API и сервисы» → «Экран согласия OAuth» (в новом интерфейсе «Google Auth Platform» → «Аудитория») → статус публикации **«В производстве» (In production)**. Подавать на проверку (verification) не нужно, приложение остаётся «непроверенным» и это нормально для своего канала.
   Зачем: в статусе «Тестирование» refresh-токен живёт 7 дней, потом облако перестанет заходить. Это подтверждают форумы и разбор Google, но в одном старом треде есть сообщение о 7 днях и после публикации, поэтому после переключения проверьте токен через неделю (`python3 scripts/yt_check.py`).
2. **Отозвать старый доступ**, чтобы Google выдал новый refresh-токен: https://myaccount.google.com/permissions → приложение проекта → «Удалить доступ». Токены, выданные в режиме «Тестирование», сохраняют 7-дневный срок, поэтому нужен новый.
3. **На Mac** в папке `~/KapiStudio/kapi-youtube` выполнить `python3 scripts/auth.py`, войти аккаунтом канала. Google покажет «Приложение не проверено»: «Дополнительно» → «Перейти». Новый токен сохранится в `secrets/token.json`.
4. Скопировать токен в буфер, не открывая файл и не вставляя в чат: `pbcopy < ~/KapiStudio/kapi-youtube/secrets/token.json`
5. Project settings → облачная среда «ютуб» (шестерёнка) → переменные окружения → добавить `YT_TOKEN_JSON`, вставить из буфера. Новая сессия подхватит.

Честно про безопасность: переменная окружения хранится в настройках среды открытым текстом (видна вам, а в сессиях любой код читает её). Среда личная, токен ограничен загрузкой. Если подозрение на утечку: https://myaccount.google.com/permissions → удалить доступ, и повторить шаги 2–5.

## Проверка и загрузка (в свежей облачной сессии)

```
pip install -r scripts/requirements.txt
python3 scripts/yt_check.py                       # покажет канал, ничего не загружает
python3 scripts/upload.py video.mp4 --meta plan/short1/youtube.json --made-for-kids no --dry-run
python3 scripts/upload.py video.mp4 --meta plan/short1/youtube.json --made-for-kids no
```

Скрипт печатает ссылку Studio и текст закреплённого комментария. Дальше в Studio: проверить, нажать «Опубликовать».

## Ограничения и подводные камни

- Квота YouTube API: по умолчанию 10 000 единиц в день, загрузка стоит около 1650, то есть до 6 загрузок в сутки на проект. Два Шортса в день укладываются.
- Приватность принудительная: у непроверенного API-проекта публичная загрузка не пройдёт. Публикация вручную в Studio.
- Обложка через API (`thumbnails.set`) для Шортсов может не примениться: скрипт не падает, а пишет предупреждение. Тогда кадр выбирается в Studio (для Short #1 это 21,2 с).
- Плейлист «Kapi in the League» добавляется вручную в Studio: для этого токену нужны более широкие права, которых мы ему не даём.
- Если `yt_check.py` пишет `invalid_grant`: токен отозван или протух, повторить шаги 2–5.
